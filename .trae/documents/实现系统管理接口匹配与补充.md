# 实现系统管理接口匹配与补充

## 问题分析

前端接口列表（原`/systemManage/`前缀）：
1. `fetchGetRoleList` - GET /systemManage/getRoleList
2. `fetchGetAllRoles` - GET /systemManage/getAllRoles (获取所有启用的角色)
3. `fetchGetUserList` - GET /systemManage/getUserList
4. `fetchGetMenuList` - GET /systemManage/getMenuList/v2
5. `fetchGetAllPages` - GET /systemManage/getAllPages (获取所有页面)
6. `fetchGetMenuTree` - GET /systemManage/getMenuTree

后端现有接口（`/admin/sys/`前缀）：
1. 角色管理：GET /admin/sys/role/list
2. 用户管理：GET /admin/sys/user/list
3. 菜单管理：GET /admin/sys/menu/list, GET /admin/sys/menu/tree

## 实现计划

### 1. 角色管理模块修改
- **文件**：`backend/modules/admin/endpoints/sys/role.py`
- **添加**：`GET /admin/sys/role/all` 接口，获取所有启用的角色
- **修改**：在 `RoleService` 中添加 `get_all_roles` 方法

### 2. 用户管理模块修改
- **文件**：`backend/modules/admin/endpoints/sys/user.py`
- **保持不变**：现有接口已满足需求

### 3. 菜单管理模块修改
- **文件**：`backend/modules/admin/endpoints/sys/menu.py`
- **添加**：`GET /admin/sys/menu/pages` 接口，获取所有页面
- **修改**：在 `MenuService` 中添加 `get_all_pages` 方法

### 4. 前端接口路径更新
- **文件**：`frontend/src/service/api/system-manage.ts`
- **更新所有接口路径**：将 `/systemManage/` 前缀改为 `/admin/sys/`
- **具体映射**：
  - `getRoleList` → `/admin/sys/role/list`
  - `getAllRoles` → `/admin/sys/role/all`
  - `getUserList` → `/admin/sys/user/list`
  - `getMenuList/v2` → `/admin/sys/menu/list`
  - `getAllPages` → `/admin/sys/menu/pages`
  - `getMenuTree` → `/admin/sys/menu/tree`

### 5. 测试验证
- 确保所有接口都能正常响应
- 验证返回数据结构与前端期望一致

## 技术要点
- 利用现有模块结构，避免创建新模块
- 保持接口路径统一为 `/admin/sys/` 前缀
- 补充缺失的业务逻辑到对应服务层
- 确保前端接口路径更新后能正常调用
