# 任务管理 · 任务列表新增「复制」按钮

**日期**: 2026-08-03
**提出者**: 用户

## 需求概述

任务列表（`任务列表` Tab）每行操作列新增「复制」按钮：点击后打开与「新增任务」相同的弹窗，把当前任务的所有业务信息（任务名、类型、地图、点位、机器人、播报、定时配置）回填进去，**排除 id / 创建时间 / 执行时间等由后端自动生成的字段**；保存后即新增一条全新任务，其余逻辑不变。

## 关键决策

- **后端零改动**：复制 = 用源任务数据走现有 `POST /task/manage/add`（`fetchCreateTask`）。`id/created_at/updated_at/enabled/status/last_run_at` 等全部由后端模型层默认值自动生成；点位 `points` 提交时本就不带 `id/task_id`，自动建新点位。
- **任务名直接复用源任务原名**（用户选定），不做后缀；`name` 无唯一约束（`task.py` 仅 `String(20) NOT NULL`），同名合法。
- **权限复用 `task:add`**（复制本质是新增），不新增后端权限种子/菜单种子。
- **不污染全局类型**：未给通用 `NaiveUI.TableOperateType` 加 `'copy'`（否则会迫使 ~10 个无关 drawer 的 `Record<TableOperateType,string>` 标题映射补 `copy` 键）。改为把通用 hook `useTableOperate` 泛型化（`ExtraOperate extends string = never`），task 模块以 `useTableOperate<Api.Task.Task,'copy'>` 启用局部 `'copy'`，并在列表页本地实现 `handleCopy`。
- **复用提交逻辑**：弹窗 `handleSubmit` 本就是 `isEdit ? fetchUpdateTask : fetchCreateTask`，`isEdit = operateType==='edit'`；只要 copy 走非 edit 的 operateType，提交自动命中新增接口，成功提示走 `addSuccess`。

## 实现范围（纯前端 4 文件）

- `frontend/src/typings/naive-ui.d.ts`：**未改动**（保持 `TableOperateType='add'|'edit'`）。
- `frontend/src/hooks/common/table.ts`：`useTableOperate<TableData, ExtraOperate extends string = never>` 泛型化，`operateType` 类型扩为 `NaiveUI.TableOperateType | ExtraOperate`；不新增 handleCopy（避免污染通用 API）。
- `frontend/src/views/task/modules/task-list-tab.vue`：解构 `openDrawer` + 泛型调用；本地 `handleCopy(id)`（`operateType.value='copy'` + `jsonClone` 行 + `openDrawer`）；操作列在「编辑」后加「复制」按钮（`task:add` 权限）；操作列宽 320→380、`scroll-x` 1300→1360。
- `frontend/src/views/task/modules/task-operate-drawer.vue`：`Props.operateType` 类型改为 `NaiveUI.TableOperateType | 'copy'`；`title` computed 加 `copy→'复制任务'`；`handleInitModel` 回填条件由 `==='edit'` 改为 `==='edit' || 'copy'`（共享整套回填 + `fetchGetTask` 详情拉取）；`isEdit`/`handleSubmit` 不动。
