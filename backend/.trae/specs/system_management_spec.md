# 系统管理模块规范文档

## 1. 项目概述

本规范文档基于 SmileX-Fastapi-Cloud 项目，旨在完善系统管理模块的功能实现，包括角色管理、字典管理、菜单管理和系统配置等功能。文档详细说明了各功能模块的需求、接口规范、数据验证、错误处理和验收标准，以及实现步骤和测试要求。

## 2. 功能需求

### 2.1 角色管理

#### 2.1.1 添加角色功能

- **功能描述**：允许管理员创建新的角色，设置角色名称、编码、描述、状态等信息
- **接口需求**：
  - 接口地址：`POST /api/admin/sys/role/add`
  - 请求方法：POST
  - 请求体：
    ```json
    {
      "name": "角色名称",
      "code": "role_code",
      "description": "角色描述",
      "status": true,
      "sort": 0,
      "menu_ids": [1, 2, 3]
    }
    ```
  - 响应格式：
    ```json
    {
      "code": 200,
      "msg": "创建角色成功",
      "data": {
        "id": 1,
        "name": "角色名称",
        "code": "role_code",
        "description": "角色描述",
        "status": true,
        "is_default": false,
        "is_system": false,
        "sort": 0,
        "created_at": "2024-01-01T00:00:00",
        "updated_at": null,
        "menu_ids": [1, 2, 3]
      }
    }
    ```
- **数据验证**：
  - 角色名称：必填，最大长度100
  - 角色编码：必填，最大长度100，且唯一
  - 角色状态：必填，布尔值
  - 排序号：必填，整数
  - 菜单ID列表：可选，整数数组
- **错误处理**：
  - 角色编码已存在：返回409 Conflict错误
  - 数据验证失败：返回422 Unprocessable Entity错误
  - 服务器内部错误：返回500 Internal Server Error错误

#### 2.1.2 配置菜单权限功能

- **功能描述**：允许管理员为角色分配菜单权限，控制角色可访问的系统功能
- **接口需求**：
  - 接口地址：`POST /api/admin/sys/role/{role_id}/menus`
  - 请求方法：POST
  - 请求体：
    ```json
    [1, 2, 3]
    ```
  - 响应格式：
    ```json
    {
      "code": 200,
      "msg": "分配菜单权限成功",
      "data": {
        "id": 1,
        "name": "角色名称",
        "code": "role_code",
        "description": "角色描述",
        "status": true,
        "is_default": false,
        "is_system": false,
        "sort": 0,
        "created_at": "2024-01-01T00:00:00",
        "updated_at": "2024-01-01T00:00:00",
        "menu_ids": [1, 2, 3]
      }
    }
    ```
- **数据验证**：
  - 角色ID：必填，整数，且存在
  - 菜单ID列表：必填，整数数组
- **错误处理**：
  - 角色不存在：返回404 Not Found错误
  - 系统内置角色禁止修改：返回403 Forbidden错误
  - 数据验证失败：返回422 Unprocessable Entity错误
  - 服务器内部错误：返回500 Internal Server Error错误

### 2.2 字典管理

#### 2.2.1 修复字典管理列表422问题

- **问题描述**：当前字典管理列表接口使用了bool类型的查询参数，前端传递字符串类型的状态参数时会导致422错误
- **修复方案**：参考角色管理的实现，将查询参数类型改为字符串类型，并添加参数解析函数
- **接口需求**：
  - 接口地址：`GET /api/admin/sys/dict/list`
  - 请求方法：GET
  - 查询参数：
    - name：字典名称，支持模糊查询
    - code：字典编码，支持模糊查询
    - status：字典状态，字符串类型（"true"/"false"）
    - is_system：是否为系统内置字典，字符串类型（"true"/"false"）
    - page：页码，从1开始
    - page_size：每页条数，最大200
  - 响应格式：
    ```json
    {
      "code": 200,
      "msg": "success",
      "data": {
        "records": [
          {
            "id": 1,
            "name": "字典名称",
            "code": "dict_code",
            "description": "字典描述",
            "status": true,
            "is_system": false,
            "sort": 0,
            "created_at": "2024-01-01T00:00:00",
            "updated_at": null
          }
        ],
        "page": 1,
        "page_size": 10,
        "total": 1,
        "total_pages": 1
      }
    }
    ```
- **数据验证**：
  - page：必填，整数，大于等于1
  - page_size：必填，整数，大于等于1，小于等于200
- **错误处理**：
  - 数据验证失败：返回422 Unprocessable Entity错误
  - 服务器内部错误：返回500 Internal Server Error错误

### 2.3 菜单管理

#### 2.3.1 修复添加菜单功能

- **问题描述**：前端没有调用添加菜单功能的接口，导致无法创建新菜单

- **接口需求**：
  - 接口地址：`POST /api/admin/sys/menu/add`
  - 请求方法：POST
  - 请求体：
    ```json
    {
      "parent_id": null,
      "name": "菜单名称",
      "path": "/menu/path",
      "component": "MenuComponent",
      "redirect": null,
      "permission": "menu:view",
      "meta_title": "菜单标题",
      "meta_icon": "menu-icon",
      "meta_hidden": false,
      "meta_affix": false,
      "meta_breadcrumb": true,
      "status": true,
      "type": "menu",
      "sort": 0
    }
    ```
  - 响应格式：
    ```json
    {
      "code": 200,
      "msg": "创建菜单成功",
      "data": {
        "id": 1,
        "parent_id": null,
        "name": "菜单名称",
        "path": "/menu/path",
        "component": "MenuComponent",
        "redirect": null,
        "permission": "menu:view",
        "meta_title": "菜单标题",
        "meta_icon": "menu-icon",
        "meta_hidden": false,
        "meta_affix": false,
        "meta_breadcrumb": true,
        "status": true,
        "type": "menu",
        "sort": 0,
        "created_at": "2024-01-01T00:00:00",
        "updated_at": null
      }
    }
    ```
- **数据验证**：
  - 菜单名称：必填，最大长度100
  - 菜单类型：必填，枚举类型（menu/dir/ext）
  - 菜单状态：必填，布尔值
  - 排序号：必填，整数
- **错误处理**：
  - 数据验证失败：返回422 Unprocessable Entity错误
  - 服务器内部错误：返回500 Internal Server Error错误

### 2.4 系统配置

- **功能描述**：允许管理员管理系统配置项，包括查看、创建、更新、删除配置
- **接口需求**：
  - 获取配置列表：`GET /api/admin/sys/config/list`
  - 获取配置详情：`GET /api/admin/sys/config/id/{config_id}`
  - 通过键名获取配置：`GET /api/admin/sys/config/key/{config_key}`
  - 获取配置值：`GET /api/admin/sys/config/value/{config_key}`
  - 创建配置：`POST /api/admin/sys/config`
  - 更新配置：`PUT /api/admin/sys/config/{config_id}`
  - 批量更新配置：`PUT /api/admin/sys/config/batch/update`
  - 批量重置配置：`PUT /api/admin/sys/config/batch/reset`
  - 删除配置：`DELETE /api/admin/sys/config/{config_id}`
- **数据验证**：
  - 配置键名：必填，最大长度100，且唯一
  - 配置值：必填
  - 配置类型：必填，枚举类型（string/number/boolean/json）
  - 配置分组：必填，枚举类型（system/security/notification/storage）
- **错误处理**：
  - 配置不存在：返回404 Not Found错误
  - 配置键名已存在：返回409 Conflict错误
  - 系统内置配置禁止修改：返回403 Forbidden错误
  - 数据验证失败：返回422 Unprocessable Entity错误
  - 服务器内部错误：返回500 Internal Server Error错误

## 3. RBAC权限管理规则检查

### 3.1 基本规则检查

- **用户-角色关联**：确保用户可以分配多个角色
- **角色-菜单关联**：确保角色可以分配多个菜单权限
- **权限继承**：确保用户可以继承其所有角色的权限
- **超级管理员**：确保超级管理员拥有所有权限，不受角色限制

### 3.2 权限分配检查

- **角色创建**：确保创建角色时可以同时分配菜单权限
- **角色编辑**：确保编辑角色时可以修改菜单权限
- **用户角色分配**：确保可以为用户分配多个角色
- **权限验证**：确保系统在访问受控资源时验证用户权限

### 3.3 安全性检查

- **权限边界**：确保用户只能访问其权限范围内的资源
- **权限提升**：防止用户通过非授权方式提升权限
- **权限审计**：确保权限变更有日志记录
- **默认权限**：确保新用户没有默认权限
